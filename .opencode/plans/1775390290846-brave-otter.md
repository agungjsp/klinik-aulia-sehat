# Localization Plan (ID + EN Full App)

## Objective
Implement full-app localization using `react-i18next` in this React + Vite + TanStack Router codebase, with persisted language preference and consistent date/time localization across all routes.

## Scope
- Add i18n infrastructure (`i18next`, `react-i18next`, language detection, resources).
- Migrate all major UI copy in shell + public routes + internal routes to translation keys.
- Unify locale-aware date rendering (remove hardcoded `date-fns/locale/id` and browser-default locale calls).
- Translate validation/toast/common status labels used across the app.

## Non-goals
- No backend localization changes.
- No runtime translation CMS integration (static bundled resources only for v1).
- No route structure/auth logic refactor.

## Key Architecture Decisions
1. Use `i18next` + `react-i18next` + `i18next-browser-languagedetector`.
2. Keep translation resources local (bundled JSON/TS files) with fallback language `id`.
3. Persist user language via a dedicated Zustand store (same persistence pattern as auth store).
4. Centralize locale mapping for `date-fns` and `Intl` in one helper module.
5. Use route/domain namespaces to keep key ownership clear and reduce merge conflicts.

## Namespace Strategy
- `common`: global actions, shared labels, table/empty/loading states.
- `nav`: sidebar/app-shell labels.
- `auth`: login and auth feedback.
- `dashboard`: `/` route.
- `display`: `/display` route.
- `cekAntrean`: `/cek-antrean` route.
- `queue`: antrean workflow texts shared by administrasi/perawat/perawat-asisten/dokter/components.
- `schedule`: `/jadwal` and schedule-related shared labels.
- `reports`: `/laporan` route.
- `master`: `/master/*` routes.
- `settings`: `/pengaturan/*` routes.
- `errors`: `/403`, `/no-access`, and generic error copy.
- `validation`: form/zod validation messages.
- `toast`: reusable success/error feedback messages.

## Implementation Phases

### Phase 1 - Dependencies and Core i18n Setup
1. Add dependencies in `package.json`:
   - `i18next`
   - `react-i18next`
   - `i18next-browser-languagedetector`
2. Create i18n bootstrap and resource structure:
   - `src/lib/i18n/index.ts`
   - `src/lib/i18n/config.ts` (supported languages, fallback, namespace list)
   - `src/lib/i18n/resources/id/*.json`
   - `src/lib/i18n/resources/en/*.json`
3. Wire app bootstrap:
   - `src/main.tsx` import i18n init before app render.

### Phase 2 - Persisted Locale State + App-level Wiring
1. Add locale store:
   - `src/stores/locale.ts` (persisted `language`, setter)
2. Export locale store:
   - `src/stores/index.ts`
3. Root synchronization:
   - `src/routes/__root.tsx`
   - Sync Zustand language to `i18n.changeLanguage(...)` and set `document.documentElement.lang`.
4. Add reusable locale hook:
   - `src/hooks/use-locale.ts` (read current language + change handler).

### Phase 3 - Shared UI Migration (Shell First)
1. Add language switcher in authenticated shell:
   - `src/components/layout/app-layout.tsx`
2. Translate sidebar labels and user-menu labels:
   - `src/components/layout/sidebar.tsx`
3. Translate shared queue header component:
   - `src/components/antrean/antrean-header.tsx`
4. Translate shared data-table static labels (if present):

## Translation Migration Rules
1. Use semantic keys (e.g. `queue.callNext`) not sentence keys.
2. Keep temporary fallback text only during migration; remove before final completion.
3. For repeated text, key must live in `common`/`toast`/`validation` instead of route namespace.
4. Interpolated strings must use named params (`{{count}}`, `{{name}}`, `{{date}}`).
5. Keep machine date formats (`yyyy-MM-dd`) for API/query/input values unchanged; localize display text only.

## Risks and Mitigations
1. Mixed-language screens during migration.
   - Mitigation: complete route-by-route migration and review before considering phase done.
2. Date inconsistency between components.
   - Mitigation: ban browser-default locale usage and route all date display via locale helper.
3. Missing translation keys.
   - Mitigation: enable dev missing-key logging + fallback language `id` + manual navigation smoke tests.
4. Large PR complexity.
   - Mitigation: execute in phased commits/PR slices (core infra -> shell -> routes group-by-group).

## Verification Plan

### Automated checks
1. Install/refresh dependencies: `bun install`
2. Run lint: `bun run lint`
3. Run build/typecheck: `bun run build`
4. Run app: `bun dev`

### Functional checks (manual)
1. Language switcher exists in authenticated shell and toggles `id/en` instantly.
2. Language preference persists after full refresh and re-login.
3. Sidebar/nav/app-shell labels switch correctly.
4. Public pages (`/login`, `/cek-antrean`, `/display`) fully switch language.
5. Internal pages for each route group render translated labels/messages.
6. Dates and day/month names change with selected language on:
   - Dashboard (`/`)
   - Display (`/display`)
   - Cek Antrean (`/cek-antrean`)
   - Antrean header component flows
   - Calendar component
7. Validation messages and toast feedback use selected language.
8. No missing-key console errors while navigating all major routes.

## Acceptance Criteria
1. App supports `id` and `en` globally with persisted user preference.
2. All route groups listed in this plan have localized user-visible copy.
3. Shared shell/components/domain status labels are localized.
4. Date/time display is locale-consistent and no longer tied to hardcoded Indonesian or browser default.
5. `bun run lint` and `bun run build` pass.
6. `docs/localization.md` and `.opencode/CHANGELOG.md` are updated.
