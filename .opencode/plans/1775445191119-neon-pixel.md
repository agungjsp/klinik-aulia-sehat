# Plan: Treat `quota = null` or `0` as Unlimited

## Objective
Unify frontend quota semantics so schedule quota is considered **unlimited** when backend sends `quota: null` or `quota: 0`.

## Confirmed Product Decision
- Poli Gigi is also included in this rule: `quota = 0` is valid and means unlimited.

## Scope
- In scope: quota interpretation, full/remaining calculation, schedule selection disable rules, submit-disable rules, and schedule form validation/display consistency.
- Out of scope: backend API contract, backend quota enforcement logic, DB changes.

## Recommended Approach

### 1) Centralize quota semantics in one shared utility
Create a small helper module to prevent duplicated conditional logic.

- **New file:** `src/lib/quota.ts`
- Add helper(s):
  - `isUnlimitedQuota(quota)` -> `true` for `null`, `undefined`, or `0`
  - `getQuotaUsage({ quota, used })` -> standardized `{ normalizedQuota, used, remaining, isFull, isUnlimited }`
- Rule set:
  - `quota == null || quota === 0` => unlimited
  - finite quota (`> 0`) => regular remaining/full calculation
  - defensive behavior for invalid negatives: treat as unlimited (prevents false hard-blocks)

### 2) Update queue/header quota summary logic
Apply the shared helper so `quota: 0` is never treated as full.

- **Modify:** `src/hooks/use-antrean-summary.ts`
  - Replace direct null/undefined checks and raw remaining/full math with quota helper.
  - Ensure `quotaInfo` returns `null` for unlimited schedules.

- **Review display:** `src/components/antrean/antrean-header.tsx`
  - Confirm no “full” indicator appears for unlimited schedules.
  - Keep existing display behavior for finite quota.

### 3) Update schedule picker and selected schedule summary
Ensure schedule cards and summary handle `0` the same as `null`.

- **Modify:** `src/components/schedule/schedule-picker.tsx`
  - Use quota helper in `scheduleInfoList` mapping.
  - Ensure card disable/full badge only for finite quota with no remaining slots.
  - Treat `quota: 0` as unlimited label (`Tanpa batas kuota`), not as `Penuh`.
  - Keep progress bar only for finite quota.

### 4) Update admin queue registration guard
Keep form submission blocked only when finite quota is truly full.

- **Modify:** `src/routes/administrasi/antrean.tsx`
  - Replace local quotaInfo calculation with shared helper semantics.
  - Ensure `isSubmitDisabled` does not block when selected schedule quota is `0`.
  - Keep backend error fallback handling (quota/full message + refetch) unchanged.

### 5) Align schedule management form with new semantics
Make `/jadwal` consistent with the global rule, including Poli Gigi.

- **Modify:** `src/routes/jadwal/index.tsx`
  - Update Poli Gigi validation path so `0` is valid under new rule.
  - Change quota input constraint from `min="1"` to `min="0"`.
  - Replace truthy quota checks (`s.quota`) in calendar/detail rendering with explicit finite check (`quota > 0`) so `0` is not mis-rendered.

- **Review i18n copy (only if wording becomes inaccurate):**
  - `src/lib/i18n/resources/id/schedule.ts`
  - `src/lib/i18n/resources/en/schedule.ts`

### 6) Consistency review for other queue-role pages
Ensure no duplicate quota logic remains outside shared paths.

- **Review-only:**
  - `src/routes/perawat/antrean.tsx`
  - `src/routes/perawat-asisten/antrean.tsx`
  - `src/routes/dokter/antrean.tsx`
- Validate these rely on shared `AntreanHeader`/summary behavior and need no direct quota changes.

### B) Manual end-to-end checks (`bun dev`)
1. Admin queue (`/administrasi/antrean`):
   - Schedule with `quota: null` -> selectable, not full, submit allowed.
   - Schedule with `quota: 0` -> same as unlimited (selectable, no full warning).
   - Finite quota schedule where `used >= quota` -> shows full warning, submit disabled.

2. Schedule picker component behavior:
   - Unlimited (`null`/`0`) shows unlimited text, no finite progress ratio.
   - Finite quota still shows remaining/total and full badge when exhausted.

3. Schedule management (`/jadwal`):
   - Can create/update schedule with `quota: 0` (including Poli Gigi).
   - `quota: 0` renders as unlimited semantics, not finite `0` capacity.
   - Negative values are rejected by UI validation.

4. Other queue role pages:
   - `/perawat/antrean`, `/perawat-asisten/antrean`, `/dokter/antrean`
   - Header summary does not show false full status for `quota: 0` schedules.

### C) Regression checks
- Duplicate-contact/BPJS errors still map to the same toasts.
- Backend “quota full” error handling still triggers quota-full toast + refetch.
- No `NaN`/invalid width in any quota progress visualization.
